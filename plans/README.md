# Vela — Hardening Roadmap

> Generated by a repo-wide audit loop (`ponytail-audit` for over-engineering +
> `improve` for correctness/security/performance/scaling). This index is the
> **strategy layer** for raising the codebase from "works, but with scaling and
> ledger landmines" to production-hardened. Each plan below is self-contained:
> an executor with no prior context can run it against the stamped base commit.
>
> **Base commit for all plans:** `fcd3eb9` (origin/main, PR #12).
> **Verification gates (every plan):** `npm run typecheck` → `npm run lint` →
> `npm run build`. There is **no automated test suite yet** — that gap is itself
> plan `005` and is the prerequisite for safely executing the riskier refactors.

- **BUG-08** (custom-range previous-period "off-by-1ms"): on careful reading the
  previous window is exactly the same length as the current window for any range

  sub-day ranges and is the deliberate `max(rangeLen, 1day)` clamp. Not a bug.
- **Delete `WorkspaceKpiGrid` / `WorkspaceSectionGrid`** (ponytail yagni): these
  are documented workspace primitives in `AGENTS.md`. Momentarily unused ≠ dead

  (`OPENAI_ANALYTICS_MODEL` can select a gpt-5 model), so it is forward-compat,
  not dead. Kept.

  `hooks/` example. Marginal gain vs. doc churn. Kept.

### Backlog (specified, not yet full plans)

**New in iteration 2 (fresh sweep of lighter-coverage areas):**

- **CHECKIN-RACE — staff check-in has no DB guard.** `checkInStaffAction`
  (`staff/actions.ts:~432`) does `findFirst({ checkedOutAt: null })` then `create`
  — two fast clicks/devices both insert → duplicate open time entries, which
  `calculateWeeklyHours` double-counts and check-out only half-closes. Fix: a
  Postgres **partial unique index** `(staffMemberId) WHERE checkedOutAt IS NULL`
  (raw SQL migration — Prisma can't express a `WHERE` on `@@unique`) + catch P2002
  as "already checked in". *M, MED risk (migration).*
- **DOUBLE-BOOKING — no overlap guard.** `saveAppointmentAction` and
  `saveStaffShiftAction` never check for an existing appointment/shift overlapping
  the same `staffMemberId` window before writing, so a provider can be booked into
  two slots at once (and the calendar's utilization/"Next up" logic assumes
  exclusive slots). **Product decision needed:** hard-block vs. warn. Fix: query
  overlapping CONFIRMED/PENDING rows in the window (excluding the edited id) and
  reject/warn. *M, MED.*
- **OVERNIGHT-HOURS — business-hours validation can't represent past-midnight
  clinics.** `isInsideBusinessHours` / `parseDateTime` (`calendar/actions.ts`)
  assume same-day `start < end`; a clinic configured `10:00→02:00` has every
  evening booking rejected with a generic "outside operating hours". **Product
  decision:** do pilot clinics need overnight hours? If yes, parse `endAt` onto the
  next day when `endTime <= startTime` and handle wrap-around windows. Merge with
  **BUG-07** (the same validation). *M, MED.*
- **STAFF-DIR-UNBOUNDED — staff directory loads every month-to-date appointment
  per staff member with no `take`.** `staff/page.tsx:~71` hydrates all appointments
  for all staff just to compute count aggregates. Same class as PERF-01/004 — fix
  with grouped `count` queries instead of row hydration. Bundle with plan 004. *M,
  LOW–MED.*

**From iteration 1:**

- **PERF-02 — convert-to-client indexed phone lookup.** Today still scans the
  whole client table in JS for one phone match. Safe fix needs a normalized-phone
  column + `@@unique([businessId, normalizedPhone])` so the fuzzy match becomes
  an indexed `findFirst`. Bundle with plan 003's search-endpoint work (same
  normalization). *S–M, MED risk (backfill existing rows).*
- **SEC-01 — server-side upload validation.** MIME/size are validated only in the
  browser (`media-storage-client.ts`); the server stores client-reported
  `mimeType`/`fileSize`. Add a Supabase Storage bucket policy (provider-enforced
  MIME + size cap) and stop trusting client-reported metadata. *M, LOW risk.
  Bounded blast radius — private bucket, signed URLs, per-uploader prefix.*
- **SEC-03 — uniform Zod on `saveX` actions.** `saveClientAction`,
  `saveAppointmentAction`, `saveStaffAction`, `saveSettingsAction`, etc. hand-roll
  validation instead of a Zod parse (no mass-assignment today since columns are
  enumerated, but no schema guardrail and unbounded free-text). Adopt the
  per-action Zod pattern already used by the client sub-record actions. *M, LOW.*
- **SEC-04 — distributed rate limiter.** `lib/rate-limit.ts` is a per-instance
  in-memory `Map`; on Vercel the login/email throttles multiply by warm-instance
  count. Back `checkRateLimit` with Upstash Redis / Vercel KV (call sites already
  support a drop-in swap). *M, LOW. Supabase Auth is the backstop today.*
- **BUG-07 — business-hours validation.** `saveAppointmentAction` validates with
  raw `HH:mm` strings (malformed → coerced to `00:00`), and falls back to a
  hardcoded Mon–Fri 9–5 when a `businessHours` row is missing. Derive minutes from
  the parsed zoned instants; treat missing rows as closed/unknown. *M, MED.*
- **PERF-07 — conversation normalization batching.** `normalizeConversationsForBusiness`
  loads all clients + all conversations, then runs one `$transaction` per
  duplicate-phone group. Bound the work and batch. Investigate callers first
  (maintenance path, not per-request). *M, MED.*
- **ARCH-04 — split `lib/reports.ts` (2,411 lines).** God module mixing
  persistence / AI shaping / rule-based narrative / scoring / view-model building.
  Extract `reports/{scoring,narrative,ai-snapshot,charts}.ts`. *L, MED. Do after
  005 so the pure functions get characterization tests first.*
- **ARCH-05 — client sub-record CRUD envelope.** ~21 near-identical
  add/update/delete actions in `clients/actions.ts` (1,638 lines). Route through
  one parse→`requireOwnedClient`→refetch envelope helper, keeping per-model Zod
  schemas + data-mappers. *M, MED.*
- **ARCH-06 — decompose `client-details-page.tsx` (1,905 lines).** Move data
  derivations into `buildClientRecord`; split the 5 tabs into child components.
  *L, MED. Pairs with 001 (payment math moves to the builder).*
- **ARCH-07 — route bare `Intl`/`toLocale*` through `lib/time-zone.ts`.** A few
  formatting sites in `dashboard.ts`, `calendar.ts`, `analytics-ai.ts` bypass the
  zoned formatters and risk rendering in server-local time. Verify each is a real
  tz leak (some may intentionally want local), then route through `formatZoned*`.
  Add one CLAUDE.md line: arithmetic via date-fns, formatting via `time-zone.ts`.
  *S, LOW.*

   production risk (scaling, dup messages, dup reminders).

4. **004**, **006**, **ARCH-04/05/06** — the larger refactors, on top of tests.
5. Security/DX backlog (SEC-01/03/04, BUG-07, ARCH-07) interleaved by appetite.
